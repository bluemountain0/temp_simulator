# DEVELOPMENT_WORKFLOW — AI 작업 모드

모든 작업은 아래 9단계 흐름을 따른다.

```
1. 요청 이해     →  사용자 요청을 한 줄로 다시 쓴다
2. 관련 문서 확인 →  docs/PROJECT_MAP.md로 파일 식별
3. 선택적 읽기   →  관련 파일만 읽는다 (전체 스캔 금지)
4. 작업 계획      →  대형 작업이면 docs/exec-plans/active/ 작성
5. 작은 단위 구현 →  논리적 단위 1개 = 커밋 1개
6. 자체 리뷰     →  변경된 줄만 다시 본다, /code-reviewer 위임 가능
7. 테스트 실행   →  pytest tests/ -v 필수
8. 문서 업데이트 →  DECISIONS.md / TECH_DEBT.md / PROJECT_MAP.md 점검
9. 결과 요약     →  변경 파일·테스트 결과·남은 리스크 보고
```

대형 작업은 OMC의 `/ralph` 또는 `/autopilot` 활용. 단순 작업은 직접 진행.

# 5가지 작업 모드

## 모드 1. 기능 구현 모드

### 목적
사용자가 요청한 신규 기능을 코드와 테스트에 반영.

### 시작 전 읽을 문서
- `docs/PROJECT_MAP.md`
- `docs/ARCHITECTURE.md` (의존성 방향 확인)
- `docs/CODING_RULES.md`

### 반드시 확인할 파일
- 추가 위치의 모듈 (예: 솔버 추가 → `thermal_solver.py`)
- 의존 모듈 (`materials.py`, `conditions.py`)
- 관련 테스트 파일

### 작업 순서
1. 인터페이스 변경 여부 확인 (`IThermalSolver` 깨면 호출부 전부 수정)
2. 신규 함수/클래스 추가
3. 단위 테스트 추가
4. `app.py` 연동 (필요 시)
5. `pytest tests/ -v` 통과
6. `docs/PROJECT_MAP.md` 매핑 추가

### 금지사항
- 기존 솔버 시그니처 변경
- `materials.py` 상수 임의 변경
- 테스트 없이 새 솔버 추가

### 완료 조건
- 새 테스트 추가됨
- 전체 테스트 통과
- PROJECT_MAP.md에 신규 심볼 등록

### 보고 형식
변경 파일 / 추가된 테스트 / pytest 결과 / 미해결 항목

## 모드 2. 버그 수정 모드

### 목적
재현 가능한 버그를 회귀 테스트와 함께 수정.

### 시작 전 읽을 문서
- `docs/DEBUGGING.md`
- 버그 영역의 `PROJECT_MAP.md` 항목

### 반드시 확인할 파일
- 에러 스택의 모든 프레임
- 해당 영역 기존 테스트

### 작업 순서
1. 버그를 재현하는 테스트를 먼저 작성 (실패 확인)
2. 최소 수정으로 테스트 통과
3. 전체 회귀 테스트 실행
4. 원인을 `docs/DECISIONS.md` 또는 커밋 메시지에 기록

### 금지사항
- 테스트 없는 패치
- 무관한 코드 정리
- "common fix" 추측 패치 (`DEBUGGING.md` 참조)

### 완료 조건
- 재현 테스트 통과
- 기존 60개 테스트 회귀 없음

### 보고 형식
원인 / 재현 절차 / 수정 위치 / 회귀 테스트 / 부작용

## 모드 3. 리팩터링 모드

### 목적
동작 변경 없이 구조 개선.

### 시작 전 읽을 문서
- `docs/ARCHITECTURE.md` (의존성 원칙)
- `docs/CODING_RULES.md`

### 반드시 확인할 파일
- 변경 대상의 모든 호출부
- 관련 테스트 전부

### 작업 순서
1. 현재 테스트 통과 확인 (baseline)
2. 한 번에 한 가지 구조 변경
3. 각 단계마다 `pytest tests/ -v`
4. 의도하지 않은 동작 변경 발견 시 즉시 롤백

### 금지사항
- 사용자 승인 없는 대규모 리팩터링
- 테스트 기대값 변경
- API 시그니처 변경

### 완료 조건
- 전체 테스트 통과 (수정 없음)
- diff가 외과적

### 보고 형식
변경된 구조 / 라인 수 비교 / 테스트 결과

## 모드 4. 코드 리뷰 모드

### 목적
이미 작성된 코드를 검토하고 개선점 제시. **수정 안 함.**

### 시작 전 읽을 문서
- `docs/CODING_RULES.md`
- `docs/ARCHITECTURE.md`

### 반드시 확인할 파일
- 리뷰 대상 파일 전체
- 인접 호출 컨텍스트

### 작업 순서
1. 의존성 방향 위반 확인
2. SI 단위 일관성 확인
3. 매직넘버 → 모듈 상수 분리 후보 확인
4. 함수 크기 / 응집도 확인
5. 테스트 커버리지 확인

### 금지사항
- 코드 직접 수정 (제안만)

### 완료 조건
- 심각도(높음/중간/낮음) 분류된 리뷰 리포트

### 보고 형식
파일별 이슈 목록 / 심각도 / 권장 수정 / 우선순위

OMC `code-reviewer` 에이전트를 우선 활용.

## 모드 5. 문서 정리 모드

### 목적
코드-문서 불일치 해소, `docs/` 구조 업데이트.

### 시작 전 읽을 문서
- `docs/index.md`
- 정리 대상 문서

### 반드시 확인할 파일
- 정리 대상이 참조하는 코드 파일
- 코드-문서 불일치 영역

### 작업 순서
1. 문서가 언급하는 모든 심볼이 코드에 존재하는지 확인
2. 코드의 새 심볼이 문서에 등록되어 있는지 확인
3. 불일치는 **문서 업데이트**로 해소 (코드 수정 금지)
4. 확인 불가 항목은 `> ⚠ 확인 필요` 마커

### 금지사항
- 문서 정리 중 코드 수정
- 추측으로 없는 기능을 있다고 기술

### 완료 조건
- 변경된 문서 전부 일관성 검증
- `> ⚠ 확인 필요` 마커 모두 사용자에게 보고

### 보고 형식
업데이트된 문서 / 새로 추가된 심볼 / 미확인 항목
